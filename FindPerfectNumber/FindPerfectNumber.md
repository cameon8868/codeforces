# Числа на доске

## Условие задачи

Ограничение по времени на тест: 2 секунды

Ограничение по памяти на тест: 512 мегабайт

На доске записаны все целые числа от `l` до `r` включительно, каждое по одному разу.

Назовём число на доске *красивым*, если оно равно сумме всех чисел на доске, включая само это число. Например, если на доске записаны числа −4, −1, 2, 3, 5, то число 5 красивое.

Вы можете стереть любые числа с доски, но хотя бы одно число должно остаться. Найдите минимальное количество чисел, которые нужно стереть, чтобы после этого на доске было хотя бы одно красивое число. Стирать числа не обязательно, если красивое число уже есть на доске.

### Входные данные

В первой строке дано целое число `t` (1 ≤ t ≤ 10⁴), количество наборов входных данных.

Каждый набор входных данных состоит из одной строки, содержащей два целых числа `l` и `r` (−100 ≤ l ≤ r ≤ 100).

### Выходные данные

Для каждого набора входных данных выведите одно целое число: минимальное количество чисел, которые нужно стереть с доски.

### Пример

**Входные данные**
```
8
0 0
2 6
-5 -3
-2 2
-2 3
-6 2
-2 5
0 4
```

**Выходные данные**
```
0
4
2
0
0
2
3
3
```

## Решение задачи


**Идея.** Числа на доске идут подряд по возрастанию: `l, l+1, ..., r`. Красивое число должно равняться сумме всех оставшихся чисел, поэтому после каждого стирания пересчитываем сумму и проверяем, есть ли она среди оставшихся.

Стирать числа из середины не имеет смысла: набор остаётся упорядоченным, и достаточно рассматривать удаление с краёв. Поэтому считаем два варианта:

1. стираем числа слева (наименьшие);
2. стираем числа справа (наибольшие).

Для каждого варианта стираем по одному числу, пока сумма не окажется среди оставшихся чисел или не останется одно число. Ответом будет минимум из двух результатов.

**Шаги алгоритма:**

1. Заполнить вектор числами от `l` до `r`.
2. Посчитать сумму. Если она есть в векторе, ответ `0`.
3. Иначе сделать две вектора и для каждой стирать число с левого или правого края, увеличивая счётчик, пока сумма не найдётся или не останется одно число.
4. Вывести минимум из двух счётчиков.

**Сложность.** На один набор данных не больше 201 числа и столько же шагов, в каждом из которых `accumulate` и `find` за O(201). Для `t ≤ 10⁴` это укладывается в лимит.
